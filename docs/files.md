# File leases

Parallel agents editing the same files is the other collision. Instead of pasting ownership lists into every prompt, take a lease:

```bash
dibs hold 'files:src/auth/**' -m "auth refactor"         # paths from the git root; * and ? stay in one folder, ** crosses folders
dibs hold files:src/a.ts,files:docs/api.md --for 30m    # several at once
dibs run 'files:src/gen/**,test' -- ./codegen.sh        # held for exactly as long as the command runs
dibs who files:src/auth/login.ts                        # who holds it, or anything overlapping it
```

Braces name several files at once, as a shell would: `dibs hold 'files:src/blocks/{catalog.ts,__tests__/catalog.test.ts}'` holds both files, and its commas don't split the resource list. dibs's own globs are `*`, `?` and `**`.

Two leases conflict when any path could match both: the same file, a folder and anything under it, or globs some name could match both. When unsure, they conflict. A file lease waits in line like any hold, costs no memory or cores, ends the same ways (`--for`, `dibs release`, its session dying), and never waits on your own leases. Editing a path nobody leased needs no lease.

## What the guard turns away

With the guard installed (`dibs guard install`, or the plugin), the hook turns away another session's Edit, Write, MultiEdit and NotebookEdit on a leased path, and Bash commands that obviously write one: `>` and `>>` redirects, `rm`, `mv`, `cp` and `ln` onto it (or into a folder, under the source's name), `tee`, `touch`, `truncate`, `sed -i`, `perl -pi`, `dd of=`, `git rm`, `git mv`, `git restore`, `git checkout -- path` and `git checkout .`, with or without `git -C dir`, and formatters run with their write flag (`prettier --write`, `eslint --fix`, `swiftformat`, `gofmt -w` and the like). `git apply`, `git am` and `patch -p<n>` write the files their patch names: dibs reads the patch or mailbox (named, `-i file` or `< file`) and treats each file in it as an edit. A patch it can't read (a pipe, `-`, a `$VAR`, a missing file, or `patch` without `-p`) counts as writing the whole repo (for `patch`, its folder), in every worktree. `git stash`, `git stash pop`, `git reset --hard`, `git clean`, `git checkout -f`, `git switch --discard-changes`, and `--autostash` pulls and rebases rewrite files nobody named, so they count as writing the whole repo (or folder). In a repo with several git worktrees, those, and `git checkout`, `git restore` and `git clean` of named paths, only change the worktree they run in, so they answer only to leases taken from that worktree: `git stash` in one worktree goes through while someone holds `src/a.ts` from another. Every other write, an edit included, still answers to a lease on the same file from any worktree of the repo. Prefixes like `sudo`, `timeout 60`, `npx` and `xargs` don't hide a write. Paths compare the way the disk does: on macOS `SRC/A.ts` is `src/a.ts`. The refusal names the holder, their `-m` reason, how long they've held it, and `dibs when files:<path>`.

Claude Code keeps each session's scratch files in `/private/tmp/claude-<uid>/<project folder>/<session id>/`. The guard turns away any delete or write there outside the calling session's own folder, whatever `guard.files` says, because it's the person's rule: another agent may be using those files right now. That covers `rm`, `find -delete` and `find -exec rm`, `xargs rm`, `rsync --delete`, `mv` away, `truncate`, `>` redirects, and Edit or Write. It also covers deleting the root itself, a project folder, or a glob that spans sessions (`/private/tmp/claude-503/*`), under any spelling (`/tmp/...`). Variables set earlier in the same command (`S=/path; find $S ...`, `export S=...`) or in the hook's environment are read, so a path in one is checked like one typed out. A `$VAR` path dibs still can't read is turned away when its literal start names another session's folder. A recursive delete whose whole target is a variable or `$(...)` it can't read (`rm -rf $S`, `rm -rf "$S"/*`, `find $S ... -delete`) is turned away everywhere: write the path out. A literal end (`"$S/build"`) is fine. Reads are fine anywhere, and so are writes and single-file deletes in your own session's folder.

Subagents share their session's folder, so inside it the guard also turns away a recursive delete (`rm -r`, `find -delete`, `find -exec rm`, `find | xargs rm`, `rsync --delete`, `rmdir -p`; a find's filters such as `-mindepth 1` or `-mmin +180` don't change that, since it can still reach everything) of the session folder itself or its `scratchpad`. For each folder at the top of the scratchpad, dibs remembers the first agent that wrote into it (in `~/.dibs/scratch/<session>`, gone once the session's folder is). A recursive delete of one is that agent's alone: another agent of the session is turned away and told who made it. A folder a program makes counts as made by the agent whose command named it before it existed (`xcodebuild -derivedDataPath <scratchpad>/dd`, `--out=<path>`, a relative path run from the scratchpad). A folder older than that record can go if it holds 20 files or fewer, or if the deleting agent's earlier commands named it; otherwise it's turned away, since dibs can't tell whose it is. Deleting a folder whole clears its record. Either way, ask whoever made it, or have the person delete it.

Reads are never blocked, and nothing it can't read is blocked either: a path built from `$VAR` or `$(...)`, a script that writes on its own. A refusal means wait or ask the holder, not find another way to write the file.

## Which agent holds it

Leases belong to the agent that took them. Claude Code tells the hook which subagent or teammate makes each tool call, but tells the Bash command nothing, so when the hook sees an agent run `dibs hold`, `dibs run` or `dibs release` with `files:`, it leaves a note in `~/.dibs/agents` and that dibs stamps the lease with the agent (the main thread counts as one). Sibling subagents then wait for each other, can't edit each other's paths, and can't release each other's leases. A lease the main thread took covers its own subagents, since the usual pattern is a lead taking the lease and a subagent making the edit; a subagent's lease still keeps the main thread out. A lease the hook didn't see taken (no guard, `dibs` called from a script or through `$VAR`) belongs to its whole session.

On a machine limited with `dibs limit`, other machines' file leases show as `files:` without the path.
